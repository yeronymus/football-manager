# Developer Sandbox & Local Workflow Guide

This guide explains how to develop, debug, and test the **Sports Logistics & Team Engagement Platform** on a local workstation (Windows, macOS, or Linux) in complete isolation from staging and production environments.

---

## 1. Branch & Environment Isolation Rules

1. **Never develop directly on `main`**: Create feature or refactoring branches (e.g., `feat/...`, `fix/...`, `refactor/...`).
2. **Dedicated Test Bot**: Always create a separate Telegram bot via [@BotFather](https://t.me/BotFather) for local polling and Mini App testing. Never reuse production `BOT_TOKEN` credentials on a developer workstation — polling the same bot token from two hosts triggers `TelegramConflictError` and steals updates from live users.
3. **Git-Ignored Secrets**: Store local sandbox credentials exclusively in `.env.dev` (which is ignored by Git). Never commit tokens, IP addresses, tunnel URLs, or database dumps.

---

## 2. Setting Up the Local Docker Sandbox

The repository ships with [`docker-compose.dev.yml`](../docker-compose.dev.yml), which provisions an isolated local stack on non-conflicting host ports:

| Service | Container Image | Local Host Binding | Purpose |
|:---|:---|:---|:---|
| `db` | `postgres:15-alpine` | `127.0.0.1:5433` | Isolated `sports_dev` PostgreSQL database |
| `redis` | `redis:7-alpine` | `127.0.0.1:6380` | Isolated Redis (`DB 0` FSM/Cron, `DB 1` Cache, `DB 2` Streams) |
| `app` | Local build (`./app` mounted) | `127.0.0.1:8000` | FastAPI + WebApps with Uvicorn `--reload` |
| `worker` | Local build (`./app` mounted) | Internal | Aiogram polling (`USE_POLLING=True`), APScheduler, Stream consumer |
| `tunnel` | `cloudflare/cloudflared` | Optional (`--profile tunnel`) | Ephemeral HTTPS tunnel for mobile Telegram Mini App testing |

### Step-by-Step Startup

```bash
# 1. Create your local sandbox env file from the template
cp .env.dev.example .env.dev

# 2. Edit .env.dev and set:
#    BOT_TOKEN=<your_test_bot_token_from_BotFather>
#    BOT_USERNAME=<your_test_bot_username>
#    SYSTEM_OWNER_ID=<your_telegram_numeric_user_id>

# 3. Boot the stack with live hot-reload
docker compose -f docker-compose.dev.yml --env-file .env.dev up --build
```

Verify that both probes report healthy:
- Liveness: `http://localhost:8000/health/live` → `{"status": "alive"}`
- Readiness: `http://localhost:8000/health/ready` → `{"status": "ready", "checks": {"postgres": "ok", "redis": "ok"}}`
- Interactive Swagger UI (enabled automatically in `local_dev`): `http://localhost:8000/docs`

## 3. Testing Mini Apps in a Desktop Browser (`DEV_AUTH_BYPASS`)

Telegram Mini Apps normally require a cryptographically signed `initData` payload generated by the Telegram client (`Authorization: tma ...`).

When `APP_ENV=local_dev` and `DEV_AUTH_BYPASS=True` in `.env.dev`, the backend enables a strictly fenced developer header for rapid browser and curl/Playwright debugging:

```bash
# Authenticate as default DEV_USER_ID from .env.dev
curl -H "Authorization: dev" http://localhost:8000/api/dashboard/groups

# Authenticate as a specific Telegram User ID (e.g., 900001)
curl -H "Authorization: dev 900001" http://localhost:8000/api/users/me
```

> **Security Guardrail**: `app/config.py` enforces a fail-closed Pydantic `@model_validator`. If `DEV_AUTH_BYPASS=True` is ever set while `APP_ENV` is `production` or `staging`, the application refuses to boot and raises a `ValidationError`.

## 4. Testing Mini Apps on Mobile Telegram via Cloudflare Tunnel

Telegram requires `https://` URLs to open Mini Apps inside the mobile or desktop Telegram client. Use the built-in `tunnel` profile to expose port `8000` over an ephemeral `trycloudflare.com` HTTPS URL without opening router ports:

```bash
docker compose -f docker-compose.dev.yml --env-file .env.dev --profile tunnel up --build
```

1. Copy the generated `https://<random-words>.trycloudflare.com` URL printed in the `tunnel` container logs.
2. Update `WEBAPP_URL=https://<random-words>.trycloudflare.com` in `.env.dev`.
3. Restart `app` and `worker`:
   ```bash
   docker compose -f docker-compose.dev.yml --env-file .env.dev restart app worker
   ```
4. Configure your `@BotFather` test bot Menu Button URL to `https://<random-words>.trycloudflare.com/web/admin.html` (or trigger inline WebApp buttons from a test Telegram group).

## 5. Running Linting, Architecture Checks & Tests Locally (Without Docker)

For fast inner-loop TDD using SQLite in-memory fixtures (`tests/conftest.py`):

```powershell
# Windows PowerShell
$env:PYTHONPATH = "."
$env:BOT_TOKEN = "123456789:AABBCCDDEEFFGgHHiijjkklLMMNNooppQQ"

# 1. Lint & style checks
.\.venv\Scripts\ruff check .

# 2. Layer-boundary & AST health check
.\.venv\Scripts\python scripts/health_check.py

# 3. Run unit, integration, and E2E test suites
.\.venv\Scripts\pytest -v
```

```bash
# Linux / macOS
export PYTHONPATH=.
export BOT_TOKEN="123456789:AABBCCDDEEFFGgHHiijjkklLMMNNooppQQ"

uv run ruff check .
uv run python scripts/health_check.py
uv run pytest -v
```
